INFORMATIQUE / PUBLICATION NUMÉRIQUE · FIRST PRINCIPLES

Pourquoi écrire un cours deux fois quand une seule source suffit ?

Tu enseignes le protocole ARP. Il te faut une page web pour tes élèves et un PDF A4 à imprimer. Puis tu corriges une erreur. Comment éviter deux modifications, deux versions contradictoires et deux fois plus de travail ? Cette question mène à Quarto.

01 · LE PROBLÈME

Quel problème cherchait-on à résoudre ?

Imagine trois copies du même cours : cours.docx, cours.pdf et cours.html. Si tu modifies l'explication d'ARP dans Word mais oublies la page web, laquelle est la bonne ? Les formats finissent par diverger.

Il faut distinguer deux choses : le savoir (titres, phrases, exemples, images) et la forme de diffusion (écran interactif, papier paginé, diaporama).

Besoin fondamental : conserver une source de vérité et fabriquer plusieurs présentations reproductibles de son contenu.
02 · AVANT QUARTO

Comment faisait-on auparavant ?

Il n'y a pas eu un « avant Quarto » unique. Plusieurs solutions coexistaient — et existent toujours.

  1. Documents indépendants : Word ou LibreOffice pour les polycopiés, HTML écrit séparément pour le site. Flexible, mais avec un risque de désynchronisation.
  2. Export depuis un logiciel : un document bureautique ou LaTeX pouvait produire un PDF ; l'export HTML existait aussi, avec des résultats et des possibilités variables. LaTeX privilégiait historiquement la composition imprimée.
  3. Pandoc : conversion entre formats textuels et documentaires à partir d'une source structurée. Une brique essentielle existait donc déjà ; créer un site avec navigation, thème et automatisation demandait davantage d'assemblage.
  4. R Markdown, bookdown et notebooks Jupyter : association du texte et du code pour produire des rapports reproductibles, des livres et des résultats calculés. Quarto hérite largement de cette culture.

Nuance historique : « écrire une fois, publier en plusieurs formats » est plus ancien que Quarto. Ce dernier ne l'a pas inventé ; il fournit une chaîne de publication cohérente autour de cette idée.

03 · LES PREMIERS PRINCIPES

Reconstruisons Quarto

  1. Un texte doit décrire sa structure. Dans Markdown, # marque un titre et - une liste : ce n'est pas une police ou une taille figée.
  2. Une source peut être transformée. Un moteur de conversion, notamment Pandoc, interprète cette structure et la traduit vers le format choisi.
  3. Un projet a besoin de règles communes. Un thème, des options de PDF, une navigation, des références et des commandes de construction évitent de tout reconfigurer pour chaque chapitre.

Quarto est un système libre de publication scientifique et technique qui réunit ces éléments. Il utilise principalement des fichiers .qmd (Quarto Markdown), s'appuie sur Pandoc et peut produire notamment des pages HTML, des PDF, des documents Word, des livres ou des présentations.

Il peut également exploiter des notebooks et du code exécuté par les moteurs appropriés. Quarto ne signifie pas automatiquement « code exécuté » : cette fonction dépend du contenu et de la configuration.

Analogie : le fichier .qmd est une recette structurée ; Quarto orchestre la cuisine ; Pandoc aide à transformer les ingrédients ; HTML et PDF sont deux présentations du plat. L'analogie simplifie une chaîne technique qui comporte plusieurs moteurs.

Un exemple minimal

---
title: "Comprendre ARP"
format:
  html: default
  pdf: default
---

# Pourquoi ARP ?

Une machine connaît une **adresse IPv4**,
mais doit trouver l'adresse MAC sur son lien.

La commande quarto render index.qmd lance le rendu selon les formats configurés. Pour le PDF, Quarto peut recourir à Typst ou à LaTeX selon le format et les options retenus.

04 · SIMULER

Suivre une source jusqu'aux sorties

Avance dans le schéma : chaque étape révèle un rôle. Les flèches montrent une chaîne de publication simplifiée, pas les processus internes exacts de chaque moteur.

  1. 1. Le cours existe dans un seul fichier.
  2. 2. Quarto lit les métadonnées et coordonne la conversion.
  3. 3. Une sortie HTML peut servir de page web.
  4. 4. Une sortie PDF peut être composée pour l'impression.
Étape 1 sur 4

Un quiz animé en JavaScript peut vivre dans la page HTML, mais ne devient pas magiquement interactif dans un PDF. Il faut alors concevoir un équivalent imprimable, par exemple une question statique suivie de son corrigé.

05 · CHOISIR UN OUTIL

Quelles alternatives à Quarto ?

Le bon outil dépend du livrable principal : un polycopié, un livre scientifique, une documentation technique ou une application web.

OutilParticulièrement adapté àCompromis
QuartoUne source pour cours, HTML, PDF, livres et diapositives.Il faut maîtriser les formats et la configuration.
PandocConvertir des documents entre de nombreux formats.Il n'organise pas, à lui seul, tout le site pédagogique.
R MarkdownRapports reproductibles, particulièrement avec R.Son écosystème historique est plus centré sur R ; il reste maintenu.
Jupyter Book / MySTLivres scientifiques, notebooks, calculs, références.Autre chaîne de publication à apprendre.
MkDocs / ZensicalDocumentation web en Markdown.Le PDF de cours n'est pas leur sortie centrale ; les produits évoluent.
SphinxGrande documentation technique, API et références croisées.Configuration et écosystème d'extensions plus exigeants.
Astro / DocusaurusSites riches et personnalisés.Une chaîne de PDF soignés doit être conçue séparément.
LaTeX / TypstDocuments à composition typographique précise.Le site HTML complet n'est pas leur mission principale.

Deux projets, deux choix légitimes

Un site de cours SNT / BTS CIEL

Si le besoin non négociable est « un cours → HTML et PDF A4 », Quarto est un candidat particulièrement pertinent.

Une encyclopédie très interactive

Si les expériences JavaScript et un graphe 3D dominent, un site HTML/JavaScript dédié peut être plus souple. Rien n'oblige à utiliser Quarto partout.

Attention aux dates : le paysage des générateurs évolue. Pour comparer des versions et calendriers de maintenance, consulte les sites officiels avant un nouveau projet.

06 · TRANSFÉRER

Quand la source unique ne suffit-elle pas ?

Si tu veux une simulation de réseau interactive dans le navigateur et une fiche papier, le fond scientifique peut rester identique, mais l'expérience ne peut pas l'être : il faut une version statique du schéma et une consigne imprimable. La source unique facilite la cohérence ; elle ne supprime pas le travail de conception pédagogique.

Si tu veux seulement un site vitrine dynamique, produire des PDF pour chaque page peut être inutile. Si tu veux uniquement un livre imprimé, Typst ou LaTeX directement peuvent suffire. Quarto n'est donc pas une réponse universelle.
