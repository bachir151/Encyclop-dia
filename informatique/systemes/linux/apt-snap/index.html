Quel problème cherchait-on à résoudre ?

Tu veux installer un lecteur vidéo. Télécharger son programme ne suffit pas toujours : il lui faut des bibliothèques, des réglages et des fichiers associés. Comment obtenir le bon ensemble, le mettre à jour et le supprimer proprement ?

01 · LE PROBLÈME

Télécharger ne suffit pas

Un logiciel réutilise souvent du code fourni par d’autres composants : ses dépendances. Un lecteur et un éditeur vidéo peuvent partager un décodeur, mais doivent accepter sa version. Installer consiste donc à organiser des fichiers et des compatibilités, pas seulement à télécharger.

Notre question : Qui prépare les composants, qui les distribue, qui les installe et qui contrôle leurs accès ?

02 · LES PREMIERS PRINCIPES

Reconstruisons la solution

  1. Un paquet logiciel rassemble des fichiers et des informations : nom, version, architecture, dépendances, parfois scripts d’installation. Il peut contenir une bibliothèque ou de la documentation plutôt qu’une application complète. Ce paquet logiciel ne désigne pas un paquet réseau.
  2. Un dépôt organise les paquets et leur catalogue. Un serveur rend ces fichiers accessibles ; plusieurs serveurs peuvent distribuer le même dépôt.
  3. Un gestionnaire de paquets choisit les composants nécessaires et suit leur installation. Sur Debian et Ubuntu, APT organise les paquets .deb et s’appuie sur dpkg pour les installer.

Analogie : un paquet ressemble à un colis accompagné d’une fiche descriptive. Limite : ses dépendances et ses scripts peuvent modifier le système ; ce n’est pas un simple dossier à copier. Une distribution assemble un ensemble cohérent de logiciels. Le noyau Linux n’impose pas APT. Voir les métadonnées Debian et la gestion des paquets Ubuntu.

03 · LE TRAJET D’UNE COMMANDE

Comment APT trouve-t-il les paquets ?

APT lit les sources configurées dans /etc/apt/sources.list et les fichiers .sources ou .list de /etc/apt/sources.list.d/. Certains fichiers peuvent être absents selon l’installation. Les sources indiquent l’adresse du dépôt et les parties de la distribution à consulter. APT ne recherche pas le logiciel sur tout Internet. Configuration des sources.

  1. sudo apt update récupère ou actualise les catalogues disponibles. Le DNS permet de résoudre le nom du serveur en adresse IP. Dans le cas HTTPS présenté ici, une connexion réseau protégée par TLS transporte les requêtes et réponses HTTP.
  2. APT vérifie les métadonnées signées du dépôt, puis les empreintes des catalogues. Les informations validées sont conservées localement.
  3. sudo apt install htop consulte ce catalogue et l’état des paquets installés, choisit une version selon sa configuration, résout les dépendances et présente les changements.
  4. Après confirmation si elle est demandée, APT télécharge les fichiers manquants, contrôle leurs empreintes, puis fait intervenir dpkg pour dépaqueter et configurer.

Le serveur fournit des fichiers ; ton ordinateur décide du plan d’installation. APT peut aussi utiliser HTTP, des supports locaux ou des caches. Il ne remplace pas les protocoles réseau par un protocole spécial « APT ». Transport HTTP d’APT.

sudo apt upgrade met à niveau les paquets installés lorsque cela est possible sans en supprimer. sudo donne les droits d’administration. Ces exemples supposent Debian ou Ubuntu et des sources correctement configurées ; aucune commande n’est exécutée par cette page.

04 · EXPÉRIMENTER

Suivre les échanges, étape par étape

Modèle simplifié : un client, un dépôt HTTPS et aucun fichier déjà en cache. Le DNS, les relais et les multiples requêtes sont résumés. Les flèches indiquent le sens des échanges, pas une prise de contrôle à distance.

APT lit les dépôts configurés sur la machine. Aucun logiciel n’est encore téléchargé.

  1. APT lit les dépôts configurés sur la machine. Aucun logiciel n’est encore téléchargé.
  2. apt update contacte le dépôt : résolution DNS, puis requêtes HTTP sur HTTPS dans cet exemple.
  3. Le dépôt renvoie les métadonnées signées et les catalogues. APT les vérifie avant de les utiliser.
  4. apt install htop calcule localement les dépendances à partir du catalogue et de l’état installé.
  5. APT demande les fichiers .deb nécessaires au serveur, après confirmation si elle est demandée.
  6. Les fichiers .deb reviennent vers le client ; APT vérifie leurs empreintes.
  7. dpkg dépaquette et configure les paquets. Le serveur n’installe rien à distance.
Étape 1 sur 7

Observe les étapes 1 et 4 : lire les sources et calculer le plan sont des opérations locales. Les téléchargements du catalogue et des paquets sont deux opérations distinctes. Les explications de chaque étape sont aussi disponibles en texte.

05 · DE L’AUTEUR AU DÉPÔT

Qui alimente les serveurs ?

  1. Les développeurs produisent le code du logiciel.
  2. Les mainteneurs de paquets préparent son intégration à la distribution : recette de construction, dépendances et éventuelles adaptations.
  3. L’infrastructure de construction et de publication construit les paquets, applique les contrôles prévus et les intègre à l’archive.
  4. Les miroirs recopient cette archive pour répartir les téléchargements. Leur hébergeur n’est pas forcément l’auteur du logiciel.

Ce parcours décrit le modèle Debian, de façon simplifiée : les procédures exactes varient. Un éditeur peut également exploiter son propre dépôt. Ajouter une source et sa clé introduit une nouvelle relation de confiance. Construction des paquets Debian ; archive et miroirs.

Comment faire confiance aux fichiers reçus ?

La chaîne de vérification relie une clé de confiance à des métadonnées signées (souvent InRelease), puis aux empreintes des catalogues, puis aux empreintes des paquets. Une empreinte est calculée à partir du contenu d’un fichier ; elle permet de vérifier qu’il correspond au contenu annoncé.

HTTPS protège le transport ; la signature authentifie les métadonnées du dépôt. APT ne vérifie pas, dans ce mécanisme, une signature individuelle de chaque .deb. Une signature valide ne garantit ni l’absence de bug ni la bienveillance du logiciel : elle renvoie à la confiance accordée au responsable du dépôt. Chaîne de confiance APT.

06 · LES LIMITES

Que se passe-t-il si le serveur ne répond pas ?

Le DNS échoue
Le nom du serveur ne peut pas être traduit en adresse IP. Ce n’est pas nécessairement une panne du dépôt.
Le serveur est inaccessible ou trop lent
La connexion ou le transfert atteint un délai d’attente. Le nombre de nouvelles tentatives dépend de la configuration.
Un dépôt échoue pendant apt update
Les autres dépôts peuvent être actualisés. APT peut conserver un ancien catalogue et afficher un avertissement : sa connaissance des versions disponibles est alors incomplète.
Un paquet requis ne peut pas être téléchargé
APT ne peut pas terminer normalement l’installation qui en a besoin. Un ancien catalogue peut aussi pointer vers un fichier supprimé du serveur et produire une erreur 404.
Les fichiers nécessaires sont déjà présents localement
Une installation peut parfois se faire hors ligne. Il faut disposer de tous les paquets requis, pas seulement de leur catalogue.
Le dépôt redevient disponible
On peut actualiser le catalogue puis reprendre l’opération. APT ne choisit pas arbitrairement un autre dépôt sur Internet ; la redondance dépend du service et des sources configurées.

Les logiciels déjà installés ne disparaissent pas. Ils continuent normalement à fonctionner, sauf s’ils ont eux-mêmes besoin d’un service en ligne. Une panne pendant le téléchargement et une interruption pendant la configuration locale ne sont pas la même situation ; APT/dpkg ne garantit pas un retour automatique à l’état initial pour toute installation interrompue.

Lire la première erreur détaillée permet de distinguer réseau, fichier absent et vérification cryptographique. Un échec de signature ne se corrige pas en donnant des permissions à l’application. Exemple d’échec DNS et d’utilisation d’anciens catalogues ; délais réseau.

07 · UNE AUTRE ORGANISATION

Pourquoi Snap existe-t-il ?

Partager les bibliothèques facilite la coordination d’une distribution, mais lie les applications aux versions disponibles. Snap distribue une application avec davantage de ses dépendances pour réduire cette dépendance à la distribution. Cela peut dupliquer des composants ; un snap n’embarque pas forcément tout et peut utiliser une base partagée.

Un snap est un paquet ; snap est la commande ; snapd est le service qui gère installation, mises à jour et confinement. Ce n’est pas une machine virtuelle : le noyau reste celui de la machine. Documentation Snap.

sudo snap install vlc
snap list
sudo snap refresh

Ces commandes installent VLC, affichent les snaps installés et demandent leur mise à jour. Les snaps provenant du magasin se mettent normalement à jour automatiquement ; ce comportement peut être contrôlé. Gestion des mises à jour Snap.

La plupart des snaps utilisent un confinement strict : leurs accès passent par des interfaces et permissions. Les snaps classic ont un accès comparable à celui d’une application traditionnelle, dans les limites des droits de l’utilisateur. Niveaux de confinement.

Cas concret : VLC démarre mais ne lit pas une vidéo sur une clé USB. Il faut examiner les droits sur la clé et les permissions du snap. apt update actualise un catalogue ; il ne donne pas l’accès à un dossier.

Installer avec APT ou Snap et piloter un service avec systemctl sont des rôles distincts. Ils interagissent : une installation peut démarrer un service et snapd est lui-même un service.

08 · COMPARER

Et sur macOS, Windows et Android ?

Le noyau Linux n’impose pas une manière unique d’installer. Les autres systèmes doivent eux aussi organiser les fichiers, les mises à jour et les accès. Plusieurs approches coexistent dans chaque écosystème.

Des mécanismes différents pour des besoins communs

Android utilise le noyau Linux mais son organisation des applications est différente de celle d’Ubuntu. Son isolation s’appuie notamment sur des identités distinctes pour les applications. Isolation des applications Android.

Trois questions à séparer : où obtenir le logiciel (distribution), quels fichiers mettre en place (installation), à quelles ressources accéder (permissions). Un magasin facilite les deux premières ; le confinement concerne la troisième.
