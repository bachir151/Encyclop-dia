Communiquer en Ethernet sans adresse IP

Peut-on transmettre un message entre deux PC en utilisant uniquement leurs adresses MAC ? Ce TP permet de le prouver sur un réseau isolé avec Linux et Python.

BTS CIEL IRDurée : 1 h 30 à 2 hLinux · Python 3 · WiresharkTP n° 01
Objectif : construire et observer une trame Ethernet de type expérimental 0x88B5, sans en-tête IPv4 ou IPv6. Les étudiants distinguent la couche liaison (MAC, Ethernet) et la couche réseau (IP).

1. Quel problème cherche-t-on à résoudre ?

Deux équipements industriels reliés au même switch doivent échanger un petit message. Aucun serveur DHCP n'est présent et aucune adresse IP n'est configurée. Un programme classique utilisant TCP/IP ne convient pas : nous allons manipuler directement les trames Ethernet.

MAC A
Pas d'IP
⟷ Ethernet ⟷
PC B
MAC B
Pas d'IP

2. Matériel et précautions

  • Deux PC Ubuntu/Debian avec une interface Ethernet et Python 3.
  • Un câble Ethernet entre les PC, ou deux câbles et un switch dans le même VLAN.
  • Wireshark ou tcpdump pour observer les trames.
  • Accès administrateur local ; travailler sur un réseau de TP isolé, jamais sur l'interface utilisée pour une connexion SSH.

3. Manipulations

Étape A — Identifier l'interface et les adresses MAC

Sur les deux PC, lancer :

ip link show

Noter les deux adresses MAC réelles. Dans les commandes suivantes, enp2s0 est un exemple à remplacer.

Étape B — Désactiver la configuration IP sur l'interface du TP

Exécuter sur chaque machine :

sudo nmcli device set enp2s0 managed no
sudo sysctl -w net.ipv6.conf.enp2s0.disable_ipv6=1
sudo ip addr flush dev enp2s0
sudo ip link set enp2s0 up
ip addr show dev enp2s0
Vérification impérative : l'interface utilisée ne doit afficher ni inet ni inet6. Cette manipulation interrompt ses connexions IP. Ne pas utiliser la carte du TP pour conserver une session distante.

Étape C — Créer notre protocole Ethernet expérimental

Créer le fichier ethernet.py sur les deux PC. Le type 0x88B5 est réservé à des expérimentations locales. Une longueur explicite permet d'ignorer le bourrage éventuel d'Ethernet.

import argparse
import socket
import struct

TYPE = 0x88B5

def mac_bytes(mac):
    return bytes.fromhex(mac.replace(":", ""))

def mac_str(raw):
    return ":".join(f"{b:02x}" for b in raw)

def mac_locale(iface):
    with open(f"/sys/class/net/{iface}/address") as fichier:
        return mac_bytes(fichier.read().strip())

def envoyer(iface, destinataire, texte):
    contenu = texte.encode("utf-8")
    if len(contenu) > 1500 - 2:
        raise ValueError("Message trop long")
    paquet = struct.pack("!H", len(contenu)) + contenu
    trame = (mac_bytes(destinataire) +
             mac_locale(iface) +
             struct.pack("!H", TYPE) + paquet)

    with socket.socket(socket.AF_PACKET, socket.SOCK_RAW,
                       socket.htons(TYPE)) as s:
        s.bind((iface, 0))
        s.send(trame)
    print("Envoyé :", texte)

def recevoir(iface):
    with socket.socket(socket.AF_PACKET, socket.SOCK_RAW,
                       socket.htons(TYPE)) as s:
        s.bind((iface, 0))
        print("En attente d'une trame...")
        while True:
            trame, infos = s.recvfrom(65535)
            if infos[2] == socket.PACKET_OUTGOING:
                continue
            if len(trame) < 16:
                continue
            if struct.unpack("!H", trame[12:14])[0] != TYPE:
                continue
            longueur = struct.unpack("!H", trame[14:16])[0]
            message = trame[16:16 + longueur]
            if len(message) != longueur:
                continue
            print("Source :", mac_str(trame[6:12]))
            print("Destination :", mac_str(trame[0:6]))
            print("Message :", message.decode("utf-8", "replace"))

p = argparse.ArgumentParser()
p.add_argument("mode", choices=["send", "recv"])
p.add_argument("interface")
p.add_argument("mac", nargs="?")
p.add_argument("message", nargs="?")
args = p.parse_args()

if args.mode == "recv":
    recevoir(args.interface)
else:
    if not args.mac or args.message is None:
        p.error("Indiquer la MAC destination et le message")
    envoyer(args.interface, args.mac, args.message)

Étape D — Échanger un message sans IP

Sur PC B :

sudo python3 ethernet.py recv enp2s0

Sur PC A, remplacer l'adresse fictive par la MAC réelle du PC B :

sudo python3 ethernet.py send enp2s0 BB:BB:BB:BB:BB:02 "Bonjour PC B"

Résultat attendu sur B : affichage de la MAC source, de la MAC destination et du texte « Bonjour PC B ».

Étape E — Observer Ethernet dans Wireshark

Sur l'interface concernée, filtrer avec eth.type == 0x88b5. Identifier les 6 octets de MAC destination, les 6 octets de MAC source, le champ EtherType et la charge utile. Constater l'absence d'en-tête IP dans la trame.

4. Questions aux étudiants

  1. Pourquoi l'envoi fonctionne-t-il alors qu'aucun PC n'a d'adresse IP ?
  2. Quel est le rôle des deux adresses MAC dans une trame ?
  3. Pourquoi utilise-t-on une socket Linux AF_PACKET plutôt qu'une socket TCP ?
  4. Quel rôle joue l'EtherType 0x88B5 ?
  5. Modifier le texte transmis et relever la charge utile dans Wireshark.
  6. Que se passe-t-il si la MAC destination désigne une autre machine ?
  7. Pourquoi un ping IP classique ne marche-t-il pas ici ?
  8. Qu'arriverait-il si les PC étaient placés dans deux VLAN séparés ?

5. Corrigé enseignant

Afficher les réponses expliquées
  1. Ethernet peut transporter une trame au niveau liaison sans utiliser IP.
  2. Les MAC identifient les interfaces destinataire et émettrice au sein de la trame.
  3. AF_PACKET permet de produire et capter des trames Ethernet directement sous Linux.
  4. Le champ indique le protocole de la charge utile ; 0x88B5 sert ici à notre essai.
  5. Les octets de la charge utile correspondent au texte UTF-8, après le champ longueur de deux octets.
  6. En fonctionnement ordinaire, l'interface de B n'accepte pas une trame unicast destinée à une autre MAC ; l'observation en capture peut varier selon le mode promiscuous.
  7. Ping utilise ICMP au-dessus d'IP, absent de l'interface de TP.
  8. Sans pont ou mécanisme de niveau 2 entre VLAN, ces trames ne passent pas d'un VLAN à l'autre.

6. Remise en état

Sur chaque PC :

sudo sysctl -w net.ipv6.conf.enp2s0.disable_ipv6=0
sudo nmcli device set enp2s0 managed yes
sudo nmcli device connect enp2s0

Réactiver, si nécessaire, le profil NetworkManager initial. Vérifier ensuite ip addr show.

À retenir : Ethernet permet de transmettre des trames entre interfaces du même lien de couche 2 sans IP. IP est utile pour l'adressage logique et l'acheminement entre réseaux ; TCP, UDP et ICMP s'appuient sur IP.

Pour aller plus loin : transformer le script en messagerie bidirectionnelle, puis comparer l'échange avec ARP et les VLAN.
